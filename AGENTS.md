Le dépôt de référence est `TbhX/momento`, branche `main`. Le propriétaire l’a rendu public le 20 octobre 2026 pour la connexion Cloudflare ; préserver son choix de visibilité. Il a autorisé les commits et push des mises à jour demandées, après vérification. Utiliser le connecteur GitHub disponible ; ne pas remplacer ce dépôt par celui du prototype Sites ni modifier VOLTÉO.

Pour une modification de code, exécuter les tests pertinents et le build Pages avant de committer et pousser. La commande de validation complète est `pnpm test && pnpm run build:pages`. Pour des documents seulement, une relecture et un contrôle du diff suffisent. Préserver les changements du propriétaire ; aucun force-push. Si la branche refuse un push, préparer une PR et expliquer le blocage.

Cloudflare Pages attend `pages-dist`, avec `_worker.js`. Le code serveur vérifie Supabase Auth et conserve actuellement les données métier dans D1/R2. La présence de Supabase ne signifie pas que toutes les données ont été migrées vers Postgres. Ne pas annoncer les salons simulés, les paiements réels ou les fournisseurs de connexion comme opérationnels sans les avoir validés.

Connexions prioritaires demandées : Google et adresse e-mail + mot de passe, avec confirmation et récupération de compte. Les parcours e-mail et leurs modèles sont implémentés et testés ; ils restent désactivés tant que le projet, le SMTP et leurs essais réels ne sont pas configurés. `AUTH_EMAIL_ENABLED` reste `false` par défaut. Leurs compteurs et la consommation unique des autorisations de récupération utilisent encore D1 ; les porter explicitement lors de la migration métier vers Postgres. SMS uniquement si un service réellement gratuit est établi ; ne pas l’activer par défaut ni transformer un essai gratuit en engagement payant. Conserver l’offre : gratuit une entrée/jour Europe/Paris, Premium accès aux salons pendant la période active ; les limitations historiques à cinq sessions ne représentent plus l’offre retenue. Les rencontres physiques restent un teaser.

L’accès de l’application GitHub Cloudflare Workers and Pages à Momento est enregistré avec l’accord du propriétaire. Les push sur `main` sont configurés pour déclencher Pages ; vérifier le statut du déploiement après chaque mise à jour et signaler tout échec.

Les secrets restent dans les paramètres serveur Cloudflare/Supabase. L’URL du projet, sa clé publiable moderne et un secret aléatoire de cookies sont enregistrés côté serveur Pages ; aucune clé d’administration n’a été ajoutée. Google et le SMTP restent à configurer, les parcours e-mail/SMS restent désactivés dans Momento. Ne jamais versionner de clé réelle, `.env`, `.dev.vars`, export de données personnelles ou sortie de compilation. Ne pas remplacer les secrets Pages masqués par une valeur vide lors d’une mise à jour. Le fichier `deploy/pages.example.jsonc` reste un modèle.
