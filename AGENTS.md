# Momento — développement et publication

Le dépôt de référence est `TbhX/momento`, branche `main`. Le propriétaire l’a rendu public le 20 octobre 2026 pour la connexion Cloudflare ; préserver son choix de visibilité. Il a autorisé les commits et push des mises à jour demandées, après vérification. Utiliser le connecteur GitHub disponible ; ne pas remplacer ce dépôt par celui du prototype Sites ni modifier VOLTÉO.

Pour une modification de code, exécuter les tests pertinents et le build Pages avant de committer et pousser. La commande de validation complète est `pnpm test && pnpm run build:pages`. Pour des documents seulement, une relecture et un contrôle du diff suffisent. Préserver les changements du propriétaire ; aucun force-push. Si la branche refuse un push, préparer une PR et expliquer le blocage.

Cloudflare Pages attend `pages-dist`, avec `_worker.js`. Le code serveur vérifie Supabase Auth et conserve actuellement les données métier dans D1/R2. La présence de Supabase ne signifie pas que toutes les données ont été migrées vers Postgres. Ne pas annoncer les salons simulés, les paiements réels ou les fournisseurs de connexion comme opérationnels sans les avoir validés.

Le projet Pages `momento` est déployé sur `https://momento-7se.pages.dev/`. L’organisation Supabase `Momento` est créée en Free. La création de son projet avait été bloquée par le quota ; le propriétaire dit l’avoir préparée, mais le connecteur ne voit encore que Volteo et refuse les opérations sur Momento. Aucun projet/base Momento n’a été créé par nos tentatives. Ne rien appliquer à Volteo. `supabase/schemas/` contient l’état déclaratif préparé et testé localement. Voir `SUPABASE_SETUP.md` avant toute application distante.

Le propriétaire a autorisé les améliorations quotidiennes, commits et push de routine sans nouvelle confirmation. Une tâche GitHub/Cloudflare est activée chaque matin vers 8 h Europe/Paris à partir du 21 octobre 2026. Lire et mettre à jour `ROADMAP_PRODUCTION.md`, choisir un chantier réalisable, vérifier le code et le déploiement ; ne pas committer uniquement pour produire de l’activité. Ne pas supposer que le dossier local d’une exécution précédente existe. L’administration distante Supabase reste hors du périmètre de cette tâche tant que l’accès à Momento n’est pas vérifié. Aucun changement de visibilité, abonnement payant, suppression d’infrastructure/données ou activation de rencontres/ventes non validées n’est autorisé par ce suivi.

Connexions prioritaires demandées : Google et adresse e-mail + mot de passe, avec confirmation et récupération de compte. Le parcours e-mail/mot de passe reste à implémenter. SMS uniquement si un service réellement gratuit est établi ; ne pas l’activer par défaut ni transformer un essai gratuit en engagement payant. Conserver l’offre : gratuit une entrée/jour Europe/Paris, Premium accès aux salons pendant la période active ; les limitations historiques à cinq sessions ne représentent plus l’offre retenue. Les rencontres physiques restent un teaser.

L’accès de l’application GitHub Cloudflare Workers and Pages à Momento est enregistré avec l’accord du propriétaire. Les push sur `main` sont configurés pour déclencher Pages ; vérifier le statut du déploiement après chaque mise à jour et signaler tout échec.

Les secrets restent dans les paramètres serveur Cloudflare/Supabase. Ne jamais versionner de clé réelle, `.env`, `.dev.vars`, export de données personnelles ou sortie de compilation. Le fichier `deploy/pages.example.jsonc` est un modèle à compléter, pas une configuration de production déjà active.
