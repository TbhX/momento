# Momento — développement et publication

Le dépôt de référence est `TbhX/momento`, branche `main`. Le propriétaire l’a rendu public le 20 octobre 2026 pour la connexion Cloudflare ; préserver son choix de visibilité. Il a autorisé les commits et push des mises à jour demandées, après vérification. Utiliser le connecteur GitHub disponible ; ne pas remplacer ce dépôt par celui du prototype Sites ni modifier VOLTÉO.

Pour une modification de code, exécuter les tests pertinents et le build Pages avant de committer et pousser. La commande de validation complète est `pnpm test && pnpm run build:pages`. Pour des documents seulement, une relecture et un contrôle du diff suffisent. Préserver les changements du propriétaire ; aucun force-push. Si la branche refuse un push, préparer une PR et expliquer le blocage.

Cloudflare Pages attend `pages-dist`, avec `_worker.js`. `SUPABASE_DATA_ENABLED=true` sélectionne les comptes/profils, médias privés et protections Auth Postgres/Storage. Le client à cookies utilise la clé publiable et RLS ; la clé moderne serveur, séparée, sert aux compteurs, contrôle des sessions, uploads JPEG nettoyés et suppression Auth. Aucun repli D1/R2 dans ce mode. Les autres services du prototype restent à porter et refusent les actions non prêtes. Ne pas annoncer les salons simulés, paiements réels ou fournisseurs de connexion opérationnels sans validation.

Choix courant du propriétaire : inscription et connexion e-mail/mot de passe simples pour commencer, Google reporté. Le réglage Supabase `mailer_autoconfirm=true` est enregistré et le minimum natif de 12 caractères vérifié : HTTP 422 `weak_password` pour 11 caractères. `AUTH_EMAIL_MODE=basic` est préparé, sans confirmation d’adresse ni récupération/renvoi par e-mail ; une adresse auto-confirmée n’est pas une identité d’adresse vérifiée. L’activation de `AUTH_EMAIL_ENABLED=true` sur Pages a été rejetée par le contrôle automatique, qui considère encore applicable l’attente d’un domaine d’expéditeur. La variable Pages reste `false`. Ne pas contourner ce refus : obtenir une confirmation explicite du propriétaire pour ouvrir les inscriptions de production dans ce mode sans SMTP, puis reprendre uniquement ce réglage. Le code public lit la disponibilité réelle du fournisseur avant d’annoncer une inscription ouverte. Aucun domaine d’expéditeur ni SMTP de production n’est vérifié. Google et SMS restent désactivés, aucun service payant à souscrire. Gratuit : une entrée/jour Europe/Paris ; Premium : salons sans plafond quotidien pendant la période active, avec règles de capacité/sécurité. Les rencontres physiques restent un teaser.

L’accès de l’application GitHub Cloudflare Workers and Pages à Momento est enregistré avec l’accord du propriétaire. Les push sur `main` sont configurés pour déclencher Pages ; vérifier le statut du déploiement après chaque mise à jour et signaler tout échec.

Les secrets restent dans les paramètres serveur Cloudflare/Supabase. Les deux clés modernes et le secret de cookies restent exclusivement côté serveur. Vérifier les migrations `20261020113549_accounts_storage_and_session_guards` et `20261020121744_serve_private_media_through_authenticated_app` avant d’activer les comptes Postgres. La révocation doit être appliquée au Worker et à la Data API ; `auth.uid()` seul ne suffit pas pour un JWT encore signé. Aucun accès membre direct à Storage : toutes les images passent par le Worker après vérification de session et autorisation. Les rôles du nouveau backend proviennent de `private.admin_roles`, jamais de métadonnées utilisateur. Ne jamais versionner de clé réelle, `.env`, `.dev.vars`, export personnel ou compilation. Préserver les secrets Pages masqués. Le fichier `deploy/pages.example.jsonc` est un modèle.

`scripts/verify-supabase-accounts.mjs` est un essai explicite sur les vrais services avec deux identités synthétiques `@momento.invalid`, confirmations administratives sans envoi et nettoyage limité aux identités créées par le script. Il exige `--allow-disposable-accounts` et un fichier JSON d’environnement privé ; aucun secret en sortie. Les tests SQL à rollback restent réservés à une base de développement vide. Consigner séparément les réussites locales, SQL distantes, API réelles et appareils.

L’accueil public est implémenté dans `src/client/home.js` avec le style commun `experience.css`. Les écrans membre restent conditionnés par `accountReady`, après lecture du compte et présence d’un profil enregistré. Ne pas réintroduire le mur de connexion sur l’accueil ni rendre les salons accessibles aux visiteurs sans profil. `go()` garde les entrées, titres, liens internes et nettoyage des appareils cohérents. Les pages métier non raccordées affichent leur état de préparation. Les deux JPEG d’illustration sont locaux et ne sont pas des membres. Le build fournit les trois mentions de confidentialité propres à la cible autonome. La prévisualisation peut utiliser un serveur et des identités synthétiques dans un dossier temporaire isolé ; ne jamais committer ce serveur, ses réponses mockées ou annoncer ces essais comme une connexion Supabase réelle.


La migration `20261020140539_persistent_community` raccorde le catalogue des salons, les amis, les demandes et les invitations audio/vidéo. Les opérations privilégiées dérivent toujours l’acteur de la session, verrouillent les deux profils dans le même ordre et respectent blocages, consentement et limites. Ajouter un ami exige une présence commune active ou une rencontre passée récente ; une invitation exige une amitié acceptée, expire après 24 h et ne consomme aucun crédit. Accepter ne délivre aucun jeton média. Blocage et signalement annulent les demandes actives. Les écritures directes de blocage sont révoquées pour garantir l’opération atomique. `community.js` affiche ces données ; les profils fictifs et achats locaux ne sont accessibles qu’après une action explicite de démonstration. Les comptes à cookies et le client serveur désactivent les répétitions implicites PostgREST ; seul le contrôle de session conserve une répétition de lecture bornée. Avant une ouverture réelle : ordonnanceur, médias, administration/modération, pagination des liens et tests sur appareils.
